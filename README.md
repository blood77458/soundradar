# SoundRadar

一边听系统正在播放的声音，一边告诉你刚才那是什么。命中后在屏幕上弹出图标和名称。

给 Windows 用。采集的是扬声器回环（WASAPI loopback），不需要虚拟声卡，也不需要把麦克风对准音箱。程序是纯 Go 写的，单个 exe，不依赖 CGO。

当前版本 `0.7.2-p5`。

## 下载就能用

从 [Releases](https://github.com/blood77458/soundradar/releases) 下载 `soundradar-windows.zip`，解压到一个单独的文件夹。压缩包里已经有程序和一份声纹库：

```
soundradar.exe
data\library.srz
data\index.bin
```

**双击 `soundradar.exe` 就能用**：托盘区会出现一个雷达图标，同时自动做三件事——打开管理页面、开始听系统声音、打开命中悬浮窗。左键（或双击）托盘图标打开管理界面，右键是菜单：

| 菜单项 | 作用 |
|---|---|
| 打开管理界面 | 在浏览器里打开 `http://127.0.0.1:8765/` |
| 查看实时识别状态 | 同上（管理界面的「实时打分」页） |
| 显示/隐藏命中悬浮窗 | 提示悬浮窗的快捷键（默认 F9，真正切换还是按那个键） |
| 打开候选项目录 | F8 存下来的片段在这里 |
| 打开程序数据目录 | `config.json` 和 `data\` 所在目录 |
| 退出 soundradar | 停掉识别、悬浮窗和托盘图标，程序完全退出 |

命令行启动也照旧可用（在解压目录打开 PowerShell）：

```powershell
.\soundradar.exe serve --overlay --open
```

`serve` 还支持 `--tray`，在命令行方式下也加上托盘图标；`soundradar tray` 则只做「托盘 + 起一个 serve 子进程」这件事，也就是双击做的事。同一条命令重复执行不会起第二个服务：端口已经在监听时直接复用。托盘图标只有一个——被启动的 serve 子进程不会自己再注册图标。

- **F8** 把刚才大约 3 秒存进「候选项」。游戏里做完动作、听到那一声之后再按。游戏占着键盘时也能用（程序会读按键状态，不只靠系统热键消息）。
- **F9** 显示或隐藏悬浮窗。同样在游戏前台可用。悬浮窗置顶、鼠标穿透，不会抢走游戏焦点。
- 管理页面的「候选项」里试听、起名、配图标，然后新建条目或追加到已有条目。
- 采集设备默认是系统当前的播放设备。耳机名字不对时，到管理页面的「设置」里改。设置写在 exe 旁边的 `config.json`，第一次运行会自己生成。
- 某个播放端点打不开时（例如 `IAudioClient::Initialize(shared/loopback) failed: error 2290679816`），程序会自动换用可用的端点、必要时再换一种音频格式，并把"换成了哪个、为什么"打印出来。全部端点都打不开时，启动阶段会直接打印所有端点清单和"该去关掉哪些东西"的清单。用 `soundradar devices --probe` 可以随时看到每个端点能不能用、各自的混合格式。
- 声纹库是 exe 旁边的 `data\library.srz`。压缩包里的这份可以直接用来认。你后来自己录的条目也写在这个文件里，换电脑时单独备份它。索引 `data\index.bin` 可以随时重算，库比索引新时，下次开始实时识别会自动重建。

自带库按听声鉴宝的同音类整理，一条里可以有多件格子对照（名称和图片只用于显示，不参与声纹）。现有这些类：卡莫纳之星/宝石项链、金狮雕像、古董茶壶、花瓶、同音·泥板/理想国、同音·雕塑组、同音·定位组、同音·琥珀天心类、同音·大框杂项。游戏里的声音和录音环境不完全一样，认不出的用 F8 再补一条即可。

## 游戏里有杂音时（环境音过滤）

游戏里一直有环境音——风声、引擎、远处的枪声、背景音乐——这些声音会盖住你想认的那一声，让识别率掉下来。0.7.0 起程序会先做一次环境音过滤：

1. **高通**：默认 120 Hz，去掉隆隆声、风噪这些低于最低分析频段的能量；
2. **逐频点抑制**：用最近约 256 ms 的最安静时刻估计每个频点的“底噪”，再按每个频点自己的信噪比把它压下去。清晰的声音几乎不动，只有噪音的部分被压掉——这正是让余弦相似度变高的做法；
3. **自适应静音门限**：门限跟着实测噪声底走，环境吵就抬高，环境安静就还是原来的 -60 dBFS，不会空转打分；
4. **更稳的锚点**：取特征窗口时先对帧能量做平滑再找峰值。这一条其实是这次识别率提升最大的一处——一个几十毫秒的音效，它中间好几帧能量几乎一样，直接取“最响的那一帧”会被环境音左右，模板和现场窗口因此对不上（实测能差 5 帧 ≈ 27 ms）。

默认比更早的设置轻一些：强度 1.5、单频最多压 8 dB、静音门只比噪声底高 4 dB。这样较轻的拾取声不容易被门限直接丢掉；环境声很响时仍会抬高门限，避免空转打分。

这些参数写在 `config.json` 的 `noise` 段里：

```json
"noise": {
  "method": "subtract",   // subtract = 高通 + 逐频点抑制；highpass = 只做高通；off = 全关
  "highPassHz": 120,      // 高通截止频率
  "strength": 1.5,        // 过减系数：越大压得越狠
  "gainFloorDb": -8,      // 单个频点最多被压掉多少 dB
  "adaptiveGate": true,   // 自适应静音门限
  "gateMarginDb": 4,      // 门限比噪声底高多少 dB
  "gateFloorDbfs": -70    // 自适应门限的下限
}
```

注意：这些参数属于**指纹**的一部分，改动之后下次启动会拿 `data\library.srz` 里的音频重新算一遍 `data\index.bin`（库文件本身不受影响）。所以调完参数第一次启动会多等一小会儿。

## 录入时注意

F8 存下来的是一整段，真正的声音往往只有其中几十毫秒。入库时程序会对准这一小段最响的地方做声纹，前后的安静背景不会被算进去。

听起来一样的声音不要拆成好几条。两条模板太像时，识别会两边都不敢报，或者报错。只保留彼此分得开的声音，阈值按条目单独调。默认门槛大约 0.75，两条容易抢的可以再抬高。

更细的录音方法见 [录音与打标指南.md](录音与打标指南.md)，日常操作见 [使用手册.md](使用手册.md)。

## 从源码编译

需要 Go 1.27 或更高，在 Windows 上编译。不需要安装 gcc。

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
cd soundradar
.\build.ps1
```

编出来的文件是 `soundradar\bin\soundradar.exe`。脚本会关掉 CGO，依赖从 `goproxy.cn` 下载。这台机器开了 Smart App Control 时，脚本会换构建盐重编，直到这个 exe 能真正启动。

托盘图标是代码生成的（`go run ./tools/iconmake`），不依赖外部图片文件。

常用命令：

| 命令 | 作用 |
|---|---|
| `soundradar.exe`（双击或直接运行，不带参数） | 托盘图标 + 管理页面 + 实时识别 + 悬浮窗 |
| `soundradar tray` | 同上（显式写法），可加 `--no-open` / `--no-serve` |
| `soundradar devices` | 列出播放设备 |
| `soundradar serve --overlay --open` | 管理页面 + 实时识别 + 悬浮窗 |
| `soundradar serve --overlay --tray --open` | 上面这些再加托盘图标 |
| `soundradar match --wav 录音.wav` | 离线看这段录音最像库里的哪一条 |
| `soundradar index rebuild` | 手动重建指纹索引 |
| `soundradar version` | 看版本 |
